# CZCMS 当前实现审计与实施清单

更新时间：2026-08-28

## 1. 审计结论

当前项目已经形成可实际使用的 CMS 基础闭环：安全登录、RBAC 数据范围、多站点独立端口、动态语言、每语言模板、内容编辑发布、栏目与标签、媒体、URL、发布记录、用户权限、审计、系统状态和加密备份均使用真实数据库与 API。后台不再展示演示数量或伪造任务状态。

本轮已增加英语源内容到各国家分站的 AI 语境本土化闭环，并把目标范围收紧为真实“已上线模板分站”。目标由数据库动态识别，维护站、停用语言、未绑定模板和不可渲染模板均无法接收 AI 版本；新增语言分站上线后无需修改代码即可加入。生成结果统一进入待审核，不覆盖已有目标版本，也不自动发布。

系统设置下已增加统一的“AI 配置”二级栏目：可同时管理多个 OpenAI 兼容提供方、服务商预设和模型。中央页面不再展示用途分配，具体 AI 功能开发时再按需接入已启用配置。密钥使用 AES-GCM 加密保存，接口只返回配置状态和末四位；配置保存后立即生效，环境变量仅作为最后一级回退。

模板列表现已支持行内展开真实编辑工作区。每套模板按公共结构、页面模板和系统页面展示头部、尾部、首页、栏目页、内容页、单页面、搜索页和 404；文件源代码由受控 `file_key` 读取，不接受任意服务器路径。编辑器支持代码校验、Ctrl/⌘+S、撤销未保存修改、修改说明、乐观锁和修订计数。保存时再次执行 Go HTML 模板解析与危险标签检查，只形成安全草稿修订，不直接覆盖正在运行的前台模板。

## 3. 本轮修改与检查结果

### 3.1 站点上下文

- 后台先加载当前用户可访问的站点，再请求站点范围数据。
- 顶部站点选择持久化到本地；当前项使用 `menuitemradio` 和 `aria-checked` 表达。
- 内容、栏目/标签、URL、发布记录请求均附带 `site_id`。
- 切换站点时清除旧行选择和搜索条件、失效对应缓存并刷新当前模块。
- 内容编辑器有未提交修改时切换站点会确认；本地草稿继续保留。
- 页面标题区明确显示当前站点，避免管理员误操作其他分站。

### 3.2 内容批量操作

- 支持批量改为草稿、待审核、已发布、需要更新或归档。
- 支持批量设置栏目或清除栏目，自动同步 Taxonomy 实体关系。
- 服务端限制 1–100 条，逐条检查内容 ID、站点、Locale、版本和数据范围。
- 单个事务执行；任何冲突、无正文发布或校验失败均全部回滚。
- 每个内容版本生成修订快照，整体操作写入不可变审计日志。

### 3.3 定时发布安全

- `status=published` 且 `scheduled_at` 为未来时间时，后台显示“定时发布”。
- 到点前公开详情、首页内容列表、跨站语言链接和发布页面计数均排除该内容。
- 到点后由服务端时间条件自动开放，无需浏览器在线；公开缓存最多造成 60 秒可见延迟。
- 当前属于“服务端时间门”，尚不是持久化任务队列；通知、重试和单独的到点审计事件仍属于下一阶段。

### 3.4 AI 本土化目标与安全门

- 仅允许从已发布英语内容发起，目标分站由站点、Locale 和模板当前状态动态计算。
- 只有运行中站点、启用语言和可安全渲染模板会默认加入；维护站在界面显示原因但不可选择。
- POST 接口再次执行站点、语言、模板与数据权限校验，不能通过伪造请求绕过。
- AI 版本保存为“待审核 / AI 待审”，已有目标版本只跳过，不自动覆盖或发布。
- AI 未配置时明确提示并停止，不降级成机械翻译。

### 3.5 AI 配置中心

- “系统设置 → AI 配置”集中管理多个 OpenAI Chat Completions 兼容接口，业务页面不重复保存密钥。
- API Key 通过 Keyring 派生密钥并以 AES-GCM 加密入库，列表接口不返回明文或密文。
- 远程地址强制 HTTPS 且必须配置 Key；localhost/127.0.0.1 本机模型允许 HTTP 和空 Key。
- 可同时添加多个服务商、区域节点和本机模型；启停、模型和连接状态相互独立。
- 提供常用服务商接口预设和模型建议，模型 ID 仍允许自由填写；中央页面不显示用途分配。
- 修改接口受 CSRF 和 `system.manage` 权限保护，并使用版本号检测并发修改；所有变更和连接测试进入审计日志。

5. 发布回滚、缓存刷新/CDN 清除以及可验证的静态产物原子切换。

## 5. 工程建议

- 保持 Go + Chi + SQLite 的模块化单体；当前自用规模无需拆微服务。
- SQLite 写事务必须继续短小；AI、网络下载、图片处理和大型导入不得放在事务内。
- 后台原生 JS 已超过三千行，下一阶段按 `content-editor`、`site-context`、`media`、`security` 等模块拆分，但不需要改成 SPA 框架。
- 当前列表上限为 100 条；数据增长后先实现服务端分页和 FTS5，再考虑更复杂的搜索服务。
- 不开放仍未接入的数据中心，不用示例数字模拟实时状态；这一原则继续保持。

## 6. 建议实施安排

### 第一批：运营基础设施

1. 先实现 SQLite 持久化任务表和有界 Worker Pool，把预约发布、全站发布、导入和 SEO 扫描统一放入任务中心。
2. 再实现 Sitemap/robots 与 FTS5；两者都必须共用公开内容判定，保证草稿、归档和未到期预约内容不会被索引。
3. 最后补 CSV/JSON 导入导出；小数据同步导出，大数据导入必须进入任务中心并生成错误行报告。

### 第二批：内容运营效率

1. 增加独立回收站、恢复权限和保留期限。
2. 增加批量负责人、批量预约时间和超过 100 条的异步批处理。
3. 把通知改为真实实体，支持已读状态、关联对象、任务失败和安全告警。

### 第三批：AI 本土化与发布可靠性

1. 建立国家市场资料、术语库、不可改字段锁和逐字段差异审核。
2. 记录模型、提示词版本、Token/费用、失败原因和人工修改，任何 AI 结果都不得直接无审发布。
3. 增加发布回滚、缓存/CDN 精确刷新和静态产物原子切换。
