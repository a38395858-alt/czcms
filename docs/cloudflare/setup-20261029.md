后续新增子域名在 Cloudflare DNS 中管理。新子域名仍须在源站配置路由与证书；边缘通配证书不替代源站证书。

## 缓存验收

通过当前公共 DNS 查询 Cloudflare 节点，连接时保留域名 SNI 并验证 HTTPS 证书，避开本地尚未过期的旧 A 记录缓存。

| 项目 | 验收结果 |
| --- | --- |
| 六语首页 | 全部 HTTP 200，`Server: cloudflare`，带 `CF-Ray` |
| 首页 HTML | `CF-Cache-Status: DYNAMIC`、`Cache-Control: no-store` |
| `/assets/css/public.css?v=20261023.1` | 连续访问从 MISS 转为 HIT |
| `/assets/js/public.js?v=20260916.1` | 连续访问从 MISS 转为 HIT |
| `/login` | 200，DYNAMIC、no-store |
| `/admin` 未登录 | 303 跳转 `/login?next=%2Fadmin`，DYNAMIC |
| `/robots.txt` | 200，公开页面允许抓取，后台及私有路径继续排除 |
| `/sitemap.xml` | 200 |

公开静态资源与 robots 响应观察到 `max-age=14400`；站点地图仍为 `max-age=300`。
本次没有创建“缓存所有内容”规则，没有提交询盘、尝试登录或发送测试邮件。
以上验证覆盖页面访问与缓存策略，不代表已完成一次真实表单提交流程。

更新同 URL 的静态文件后，应在 Cloudflare 按 URL 清理对应缓存，或更换资源版本参数；不要对包含 CSRF/表单令牌的 HTML 强制缓存。

## 源站真实访客 IP

新增 `/etc/nginx/conf.d/cloudflare-real-ip.conf`，仅信任 Cloudflare 官方发布的 15 个 IPv4 和 7 个 IPv6 网段，使用 `CF-Connecting-IP` 恢复访客 IP。
网段来源：<https://api.cloudflare.com/client/v4/ips>，与官方 `/ips-v4`、`/ips-v6` 核对。
现有反代继续把 Nginx 校验后的 `$remote_addr` 传给 Go，应用仍仅信任回环代理。

部署备份：`/var/lib/czcms/deploy-backups/20261029T015731Z-cloudflare-realip`。
`nginx -t` 通过并已 reload，Nginx 与 CZCMS 服务均 active。
公网验证请求与源站访问日志对照，CDN 请求的访客 IP 与 `/cdn-cgi/trace` 一致；直连源站时伪造 `CF-Connecting-IP` 未被采信。

可复用配置：[cloudflare-real-ip.conf](../../deploy/ubuntu/cloudflare-real-ip.conf)。重新部署前从官方来源核对最新网段。
回退这项修改时，移除新增的真实 IP 配置文件（若事前已有同名文件则从备份恢复），运行 `nginx -t` 后 reload。
程序、数据库、SMTP、账号和源站防火墙均未修改。
