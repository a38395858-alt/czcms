# CZCMS 安全实现与运维手册

> 版本：V1.0  
> 更新：2026-08-26  
> 适用架构：Go + Chi + SQLite + 内存缓存 + 可选 Redis

## 1. 已实现的安全能力

### 身份、密码与会话

- 首次安装创建唯一系统所有者，不内置默认账号或默认密码；初始化完成后 `/setup` 永久关闭。
- 未配置安装令牌时首次初始化只接受本机回环地址；生产环境强制配置至少 32 字符的 `CZCMS_SETUP_TOKEN`。
- 密码使用 Argon2id PHC 格式：64 MiB 内存、3 次迭代、并行度 2、16 字节随机盐、32 字节摘要。
- 密码最短 12 个字符，允许密码管理器生成长随机密码；验证时限制恶意哈希参数，避免数据库篡改造成内存或 CPU DoS。
- 登录使用“IP 令牌桶 + 用户名令牌桶”双层限流；同一账户连续失败 5 次后开始 15 分钟指数锁定，最长 16 小时。
- 会话令牌为 256 位随机数，SQLite 只保存 SHA-256 摘要；每次登录创建新会话，不接受客户端指定会话 ID。
- 会话默认 30 分钟空闲过期、12 小时绝对过期；退出、账户停用和 MFA 启用可吊销会话。
- 生产 Cookie 使用 `__Host-` 前缀、`Secure`、`HttpOnly`、`SameSite=Strict` 和根路径，不设置 Domain。

### CSRF 与 MFA

- 登录和首次安装使用短期 Strict/HttpOnly Cookie 与表单令牌双重校验。
- 已登录写接口要求 `X-CSRF-Token`，传统表单要求隐藏令牌；同时校验 `Origin` 和 `Sec-Fetch-Site`。
- TOTP 密钥使用 AES-256-GCM 加密后入库；配置中的临时密钥 10 分钟过期。
- TOTP 允许前后各一个 30 秒时钟窗口，并保存最后计数器，拒绝同一动态码重放。
- 启用 MFA 后生成 10 个一次性恢复码；数据库只保存带用途隔离的 HMAC-SHA-256，使用后立即作废。

### RBAC、数据范围与审计

- 内置系统所有者、管理员、内容编辑、安全审计员四个角色和细分动作权限。
- 动作权限与 `站点 + Locale` 数据范围分开计算；`site_id=0`、`locale=*` 是显式全局范围。
- 提供用户创建、角色列表、用户列表和权限范围更新 API；不能移除最后一个有效系统所有者。
- 创建用户、修改角色/数据范围和管理员解锁账户必须再次验证操作人密码；操作人已启用 MFA 时还必须提供未使用的动态码。
- 管理后台、系统状态、审计、上传、模板、备份和权限 API 均在认证与权限中间件后。
- 登录、失败、限流、退出、MFA、权限拒绝、CSRF 拒绝、用户权限、上传、模板和备份写入审计日志。
- 站点、语言、站点语言 / 模板绑定、内容、SEO、多语言版本和软删除也写入审计日志；内容读写同时校验动作权限与 `站点 + Locale` 数据范围。
- 审计表使用 SQLite 触发器禁止更新和删除；敏感元数据键自动脱敏，单条元数据限制 16 KiB。

### 富文本、模板与上传

- 富文本经过成熟白名单清洗器，仅保留必要排版标签和安全属性；危险协议、脚本、事件属性和内嵌样式被移除。
- 媒体当前只接受 JPEG、PNG；同时检查真实 MIME、扩展名、完整解码、尺寸、总像素和文件大小，并重新编码以移除 EXIF、附加尾部和多格式载荷。
- 文件使用服务端随机名保存，不使用用户文件名作为路径；存储目录不通过静态文件服务公开。
- 模板包只允许声明式 Go HTML 模板、CSS、JSON、图片和 WOFF2，不允许 JS、SVG、软链接或服务器代码。
- 模板 ZIP 检查路径穿越、单文件与总解压大小、压缩比、文件数量、入口存在性和清单格式。
- 模板 HTML 拒绝脚本、事件属性、内嵌样式、活动标签和递归模板定义；CSS 拒绝外部 URL、`@import` 和可执行表达式。
- 在线模板编辑只接受数据库清单中的受控文件键，不接收任意路径；单文件限制 2 MiB，保存前重新执行 UTF-8、Go 模板语法和被动 HTML 安全检查。
- 模板文件使用乐观锁防止并发覆盖；每次成功保存创建修订并写审计。编辑保存只形成草稿，不直接替换当前生产模板。
- 生产环境必须配置外部防病毒扫描程序；扫描失败、超时或返回非零时拒绝文件。

### HTTPS、Redis 与备份

- 应用可直接使用 TLS 证书启动，最低 TLS 1.2；也可在受信反向代理后运行，生产环境强制 HTTPS 语义与 Secure Cookie。
- 只有明确列入 `CZCMS_TRUSTED_PROXIES` 的代理才能提供 `X-Forwarded-For`，避免伪造 IP 绕过限流。
- 生产 Redis 强制 ACL 用户名和密码；非回环地址强制 TLS，可指定 Server Name 和私有 CA。
- 业务主数据不依赖 Redis；Redis 故障时仅缓存降级，认证会话、锁定和权限仍以 SQLite 为真相源。
- SQLite 通过 `VACUUM INTO` 创建一致快照，再使用独立 256 位备份密钥进行分块 AES-256-GCM 加密。
- 每次备份自动解密到临时文件并运行 `PRAGMA integrity_check`；备份篡改会导致认证失败。
- 离线恢复命令只写入不存在的新文件，不会覆盖在线数据库：

```powershell
.\bin\czcms.exe backup-restore <备份文件名.czb> <新数据库绝对路径>
```

恢复后应在隔离环境启动并完成业务抽查，再由运维在停机窗口切换数据库；应用不会自动替换在线数据文件。

## 2. 生产环境启动要求

生产环境至少需要：

- `CZCMS_ENV=production`
- `CZCMS_COOKIE_SECURE=true`
- `CZCMS_PUBLIC_HTTPS=true`，或同时配置应用 TLS 证书和私钥
- `CZCMS_MASTER_KEY`：Base64 编码的独立 32 字节密钥
- `CZCMS_BACKUP_KEY`：Base64 编码的另一把独立 32 字节密钥
- `CZCMS_SETUP_TOKEN`：至少 32 字符随机安装令牌
- `CZCMS_ANTIVIRUS_COMMAND`：接收文件路径作为唯一参数的扫描器可执行文件
- 若使用 Redis：ACL 用户名、密码；非本机连接还必须启用 TLS

缺少上述条件时程序拒绝以 production 启动。真实 `.env`、密钥文件、备份和数据库均不得进入 Git。

## 3. 反向代理和文件权限

- 公网部署只开放反向代理的 443；Go 服务保持监听回环或私有网卡。
- 若 TLS 在代理终止，配置 `CZCMS_PUBLIC_HTTPS=true`，并只将代理 IP/CIDR 加入 `CZCMS_TRUSTED_PROXIES`。
- 数据库、WAL、密钥和备份目录只允许应用服务账户访问；上传目录禁止执行脚本。
- `/healthz` 只表示进程与 SQLite 可用，不输出版本、路径或密钥；详细状态接口需要 `system.view` 权限。
- 防病毒扫描器建议使用 ClamAV `clamscan` 包装命令，扫描超时和错误必须 fail closed。

## 4. 安全验证

本地一键检查：

```powershell
.\scripts\security-check.ps1
```

检查内容：

- `go test ./...`
- `go vet ./...`
- `govulncheck ./...`
- 原生前端 Node 测试
- 存在 GCC/CGO 时执行 `go test -race -count=1 ./...`

GitHub Actions 在 Ubuntu 上强制执行竞态检测，因此本机缺少 GCC 时不能作为合并豁免。当前测试覆盖密码、账户锁定、安全会话、CSRF、TOTP 重放、恢复码一次性、RBAC 站点/语言范围、审计、富文本 XSS、模板路径穿越、加密备份与篡改检测、旧数据库无损迁移、SEO 输入校验、内容乐观锁、修订历史、多语言版本，以及完整首次安装和登录链路。

## 5. 当前边界

- 登录限流是单进程内存桶；账户锁定持久化在 SQLite。多实例时还应在反向代理/WAF 配置全局 IP 限流。
- 防病毒能力由部署环境提供，本地开发可以不配置；生产环境不允许跳过。
- 当前支持 TOTP MFA，Passkey/WebAuthn 和 MFA 重置审批尚未实现。
- 审计表应用层不可变，但具备文件系统/数据库管理员权限的人仍可替换整个 SQLite 文件；高合规环境应外送到 append-only/WORM 日志系统。
- 备份包含 SQLite 业务数据库；媒体与模板目录还需要独立加密归档或对象存储版本化策略。
- CSP 仍允许后台现有 CSS 的内联样式属性；后续整理 CSS 后应移除 `style-src 'unsafe-inline'`。
