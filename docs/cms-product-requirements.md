# 自用多站点多语言 CMS 产品与开发需求文档

> 文档版本：V1.5  
> 文档状态：开发需求基线；Go + Chi 技术基线已经确认，可用于原型、架构、任务拆分与开发验收  
> 后台语言：简体中文  
> 当前首批启用语言：英语、德语、法语、西班牙语、意大利语、荷兰语  
> 内置预置语言库：24 种常用外贸及高消费市场语言，其他语言仍可由后台添加  
> 核心目标：高安全、高访问速度、大数据量支持、灵活伪静态、Google SEO、多语言与模板扩展
> 已锁定技术基线：Go + Chi + 原生 HTML + SQLite + 进程内存缓存 + 可选 Redis

## 1. 文档目的

后台每个页面的字段、操作、状态、权限、异常处理和验收细则见：[CZCMS 中文管理后台页面功能开发文档](./admin-page-functional-spec.md)。

本文档用于定义一套自用 CMS 的产品范围、功能模块、业务规则、非功能要求、优先级和验收标准。

本文档已确定 Go、Chi、SQLite、进程内存缓存、可选 Redis 及原生 HTML 服务端渲染技术基线，但不锁定最终云服务商。后续应在本需求基础上继续输出：

4. API 与插件扩展规范；

6. 测试、压测与上线方案。

## 2. 已确认需求

### 2.1 已确认的产品要求

1. CMS 为自用系统，后台管理界面使用简体中文。
2. 前台支持多语言，语言不能写死在程序中。
3. 管理员可以在后台自行添加、修改、停用、排序语言。
4. 系统首批启用以下六种前台语言：
   - 英语；
   - 德语；
   - 法语；
   - 西班牙语；
   - 意大利语；
   - 荷兰语。
5. 系统内置较完整的常用外贸语言预置库。除首批六种语言外，还预置繁体中文、日语、韩语、葡萄牙语、波兰语、瑞典语、丹麦语、挪威语、阿拉伯语、希伯来语、俄语、土耳其语、印地语、印度尼西亚语、越南语、泰语、马来语和罗马尼亚语。
6. 预置不等于启用。除首批六种语言外，其他语言默认停用，不生成内容、URL、Sitemap 或 `hreflang`。
7. 后续新增语言时，不应要求修改 CMS 核心代码。
8. 系统支持安装和管理多套前台模板；同一站点下，每种语言必须独立绑定一套模板套装。
9. 同一种语言在生产环境中只能有一套当前生效的模板套装，但可以保留多个草稿版本、候选模板和历史版本用于预览、切换与回滚。
10. 一套语言模板包含该语言的首页、栏目页、列表页、内容页、专题页、搜索页、404 页等完整页面模板，不能把不同主题的页面随意拼成一套线上模板。
11. 不同语言可以使用不同内容、栏目、URL、SEO 信息和完全不同的模板套装。
12. 系统访问速度要快，支持 CDN、缓存、静态化或页面预生成。
13. 系统要支持大数据量内容存储和检索。
14. 系统要支持灵活的伪静态 URL。
15. 系统需要符合 Google 技术 SEO 的基本规范。
16. 系统需要具备较高安全性和良好扩展性。
17. 多语言内容支持 AI 同步，但 AI 的工作方式必须是基于源内容语义、目标国家市场、目标 Locale 和当地搜索习惯进行本土化重写，不得把逐句直译或关键词机械翻译作为正式结果。
18. AI 可独立重写各语言版本的页面标题、H1、SEO 标题、Meta Description、Slug、摘要、正文模块、图片 Alt、内链锚文本及关键词方案；事实、产品参数、品牌名称、合规声明和不可改写术语必须保持准确。
19. 每个站点、国家市场、语言地区版本和页面都支持独立 SEO 配置；不同国家或语言版本可以采用不同关键词、搜索意图、内容结构、模板和落地页策略。
20. AI 生成内容默认只能保存为草稿或建议，必须支持字段锁定、逐字段差异对比、人工审核、版本回滚和完整审计；AI 不得覆盖人工锁定字段，也不得默认自动发布。

### 2.2 当前范围说明

- 本项目核心是内容管理与网站发布，不默认等同于完整电商系统。
- 国际物流、订单、支付、库存、仓储不是当前 CMS 核心范围。
- 系统可为以后接入物流或电商模块预留 API、自定义字段和事件接口。
- 多语言与国家市场应可分开扩展，避免以后把一种语言错误地固定绑定到一个国家。

### 2.3 已确认技术决策

1. CMS 后端语言正式采用 Go，HTTP 路由采用与标准库 `net/http` 兼容的 Chi；不混入 PHP、Node.js 或其他语言的第二套业务核心。
2. 公开前台和中文后台均由 Go 服务端模板输出原生 HTML；第一版不采用前后端分离，也不把 Vue、React 或 Nuxt 作为页面正常显示的必要依赖。
3. 服务端模板采用 Go `html/template` 及受控模板函数白名单，默认自动上下文转义；第三方模板不得执行 Go 代码、SQL、系统命令或读取任意服务器文件。
4. 第一版主数据库采用 SQLite。SQLite 是唯一持久化业务主数据源，启用 WAL、外键、`busy_timeout`、短写事务、版本化迁移和在线备份。
5. 进程内存作为 L1 热数据缓存；Redis 作为可选 L2 共享缓存、会话、限流、分布式锁、任务状态和多实例失效通知，不得把内存或 Redis 当作唯一持久化数据源。
6. 缓存读取顺序为“内存 → Redis → SQLite”；写入必须先提交 SQLite 事务，再失效内存和 Redis。Redis 故障时自动降级为“内存 + SQLite”，不能阻断公开页面和后台基本操作。
7. 公开访问以静态 HTML、增量生成和 CDN 为主；动态请求由 Go 服务直接处理。媒体文件可从本地目录起步，并通过接口兼容 S3 对象存储。
8. 第一版异步任务使用 SQLite 持久化任务表与 Go 有界 Worker Pool；需要多机消费时可增加 Redis Streams，不在初期强制部署 RabbitMQ。
9. 第一版采用模块化单体，不在没有明确瓶颈时拆分微服务；存储库接口不得泄漏 SQLite 专属 SQL 到业务层，为以后按压测结果迁移 PostgreSQL 或独立搜索服务保留边界。
10. 技术框架或主数据库再次变更时，必须形成新的架构决策并重新评估迁移、安全、备份与恢复风险。

## 3. 产品定位与设计原则

### 3.1 产品定位

本产品定位为：

> 面向多个站点和多个语言版本，具有高性能发布、灵活 URL、SEO 工程化、大数据内容管理和安全扩展能力的自用 CMS。

### 3.2 核心设计原则

1. **管理与访问分离**：后台内容管理服务与前台内容交付服务应尽量解耦。
2. **语言配置化**：语言、地区代码、URL 前缀、模板、SEO 和发布规则均通过后台配置。
3. **内容与本土化版本关联但不强绑定**：不同语言版本属于同一内容组，但可按目标市场独立改写、编辑、审核、发布和下线。
4. **内部 ID 稳定**：内容内部身份不能依赖 URL，修改伪静态规则不能破坏内容关系。
5. **缓存优先**：公开页面应尽量通过页面缓存、静态生成和 CDN 返回，避免每次访问主数据库。
6. **数据分类存储**：事务数据、媒体、搜索、缓存和访问统计分别采用合适的存储方式。
7. **安全默认开启**：权限最小化、审计、上传防护、MFA、备份等不能作为可有可无的插件。
8. **SEO 自动化但可人工覆盖**：系统自动生成基础 SEO 信息，同时允许有权限的人员按语言修改。
9. **渐进式扩展**：第一版优先采用清晰、可维护的模块化架构，不为追求概念而过早拆分大量微服务。
10. **可观测、可恢复**：关键任务必须可追踪、可重试、可回滚，数据必须经过恢复演练。

## 4. 名词定义

| 名词 | 含义 |
|---|---|
| 站点 Site | 一套独立的域名、导航、模板、内容与 SEO 配置集合 |
| 语言 Language | 如英语、德语，是后台可动态添加的语言定义 |
| 地区语言 Locale | 如 `en-GB`、`de-DE`，用于格式化及 `hreflang` |
| 国家市场 Market | 如英国、美国、德国，是域名、Locale、SEO、法律信息等地区策略的配置维度 |
| 内容组 Translation Group | 表示不同语言页面属于同一主题或同一内容实体 |
| 语言版本 Content Locale | 某条内容在某种语言下的标题、正文、URL、SEO 与发布状态 |
| 主题/模板套装 Theme Package | 某种语言可绑定的一整套前台设计资源、组件和页面模板集合 |
| 页面模板 Template | 模板套装内部的首页、栏目页、内容页等具体页面类型渲染定义 |
| Slug | URL 中可读的路径片段，例如 `international-shipping` |
| 伪静态 | 动态路由呈现为易读、稳定的静态风格 URL，不等同于真实静态文件 |
| 发布 | 将已审核内容转换为前台可访问状态并刷新缓存、索引与 Sitemap |
| 回退语言 | 某些界面文案缺失时使用的备用语言，不代表自动发布重复内容页 |

## 5. 用户角色与权限范围

第一版至少支持以下角色。一个用户可以拥有多个角色，并可限定到某个站点或某些语言。

| 角色 | 主要权限 |
|---|---|
| 超级管理员 | 系统级配置、所有站点、所有用户与权限 |
| 系统管理员 | 系统设置、任务、缓存、备份、日志，不一定能读取全部内容 |
| 站点管理员 | 管理指定站点的内容、模板绑定、URL 和 SEO |
| 编辑 | 创建和修改被授权内容 |
| 本土化编辑 | 只处理被授权站点、市场和语言的本土化内容版本 |
| 审核人员 | 审核、退回、批准内容，不默认拥有系统配置权限 |
| SEO 人员 | 修改 SEO、重定向、Sitemap、关键词规划与收录设置 |
| 模板管理员 | 上传、配置、预览、发布和回滚主题模板 |
| 运维审计人员 | 查看健康状态、任务、日志和审计记录 |
| 只读人员 | 查看内容与配置，不允许修改 |

权限至少支持以下维度：

- 功能模块；
- 站点；
- 语言；
- 内容类型；
- 栏目；
- 内容状态；
- 字段；
- 创建、编辑、删除、审核、发布、回滚、导出等具体动作。

## 7. 功能需求

## 7.1 控制台

### 目标

向管理员展示系统、内容、发布、安全和性能的总体状态。

### 功能要求

- 显示站点数量、已启用语言数量、内容数量和待审核数量。
- 显示今日、近七日和近三十日发布情况。
- 显示本土化完成率、待本土化和需要更新的语言版本数量。
- 显示发布失败、索引失败、图片处理失败等任务告警。
- 显示缓存命中率、队列积压、慢查询和服务健康状态。
- 显示最近管理员登录及高风险操作。
- 显示备份时间、备份状态和最近一次恢复演练结果。
- 支持按站点筛选控制台数据。

### 验收要求

- 关键异常必须在控制台有明显提示。
- 控制台统计不得通过每次实时全表扫描获取。
- 无权限用户不得看到其他站点或语言的敏感数据。

---

## 7.2 站点管理

### 功能要求

- 创建、编辑、停用和归档站点。
- 配置站点名称、标识、主域名、备用域名和 HTTPS 要求。
- 开发环境为每个独立语言站点分配唯一 localhost 端口：后台固定使用 `8080`，首批英语到荷兰语站依次使用 `8081`–`8086`；端口可编辑且不能重复。
- 单语言站 URL 不添加 Locale 二级目录，首页为端口根路径，内容页直接使用 `/{slug}`；语言切换跨端口，正式环境跨独立域名。
- 本地端口在站点创建、端口修改、停用后动态启停，不要求手工重启 CMS；本地预览必须 `noindex, nofollow` 且不开放管理后台路由。
- 配置默认语言、启用语言及语言排序。
- 配置站点默认模板套装和默认 SEO 规则；默认模板只用于新增语言时初始化，生产环境仍以每种语言自己的绑定为准。
- 配置时区、日期格式、默认分页数量等站点参数。
- 配置静态资源域名、媒体域名和 CDN 地址。
- 支持测试环境、预发布环境和生产环境配置隔离。
- 支持站点复制，但复制前必须选择是否包含栏目、模板绑定、内容和 SEO 配置。
- 停用站点时不得直接删除站点历史数据。

### 业务规则

- 主域名全局唯一。
- 本地预览端口全局唯一，不能与后台管理监听端口冲突；生产环境不得启动 localhost 预览监听器。
- 同一域名不能同时被两个生产站点占用。
- 域名变更必须进行影响检查，并允许配置旧域名跳转。
- 生产站点的危险配置修改需要二次确认并写入审计日志。

### 7.3.2 预置、启用与发布的区别

- **预置**：语言存在于语言库中，便于选择，但不产生前台页面。
- **启用**：某个站点选择使用该语言，后台可以为其配置模板和内容。
- **发布**：该语言已绑定独立模板、完成必要配置，并至少存在经过审核的可发布内容。
- 停用的预置语言不得出现在前台语言切换器、Sitemap、`hreflang` 或公开 API 中。
- 启用语言前必须确认 Locale、URL 前缀、回退语言、文本方向和独立模板套装。
- 阿拉伯语和希伯来语启用时，模板必须通过 RTL 布局检查后才能发布。

### 7.3.3 添加与编辑语言

后台必须支持自行添加语言，字段至少包括：

- 中文显示名称；
- 语言本地名称；
- 基础语言代码，例如 `pt`；
- 地区语言代码，例如 `pt-PT`；
- `hreflang` 输出值；
- URL 前缀；
- 文本方向：LTR 或 RTL；
- 默认时区；
- 日期和时间格式；
- 数字、小数点和千分位格式；
- 默认货币与单位，仅作为扩展配置；
- 回退语言；
- 默认主题与模板；
- 是否启用；
- 是否允许搜索引擎收录；
- 排序权重；
- 备注。

### 7.3.4 语言初始化方式

新增语言时提供以下方式：

1. 只创建空语言；
2. 复制其他语言的栏目、菜单和页面结构，不复制正文；
3. 复制其他语言的全部内容作为参考初稿；复制结果不得标记为已完成本土化。

选择第三种方式时，复制后的内容必须默认为草稿并禁止收录，未经人工确认不能发布。

### 7.3.5 语言状态管理

- 语言支持启用、停用、归档和重新启用。
- 已经存在已发布 URL 的语言不得直接物理删除。
- 停用语言时必须提示受影响的内容、URL、Sitemap 和 `hreflang` 数量。
- 停用后允许配置保留旧页面、返回 410 或跳转到指定页面。
- 删除未使用语言前必须确认不存在内容、模板绑定和 URL 记录。

### 7.3.6 回退规则

- 回退语言主要用于模板界面文案、系统词典和非核心展示字段。
- 不得因为德语正文缺失，就默认在 `/de/` URL 下发布英语正文。
- 缺失的内容语言版本默认不生成公开 URL，不加入 Sitemap，也不输出对应 `hreflang`。
- 如业务确实需要展示回退正文，必须由管理员明确开启，并默认设置 `noindex`，防止产生重复页面。

### 7.3.7 国家市场与地区版本

- 国家市场和基础语言分别管理，禁止将“一种语言”永久写死为“一个国家”。
- 一个基础语言可以创建多个地区版本，例如英语可配置 `en-GB`、`en-US`、`en-CA`、`en-AU`。
- 繁体中文可以配置 `zh-HK`、`zh-TW`；葡萄牙语可以配置 `pt-PT`、`pt-BR`。
- 每个站点启用的是具体语言地区版本。一个已启用地区版本仍遵循“一种语言版本绑定一套当前生效模板”的规则。
- 国家市场配置至少包含：国家名称、ISO国家代码、Locale、时区、货币、日期格式、数字格式、度量单位、默认语言和是否启用。
- 每个市场可以覆盖SEO关键词策略、联系方式、法律页面、Cookie文案及其他地区信息。
- 后续接入物流或电商后，国家市场可继续关联税费、物流和销售规则，但这些不属于当前CMS核心。
- 如果不同国家共用相同语言和相同网站内容，可以共享内容组和模板基础设计，同时各自保留SEO、URL和地区信息覆盖能力。
- 国家市场启用前必须校验Locale、域名或URL前缀、模板、Canonical及`hreflang`策略。

### 验收要求

- 新增一种语言不需要修改或重新编译 CMS 核心代码。
- 新语言能够绑定模板、创建内容、生成 URL、生成 Sitemap 和输出 `hreflang`。
- 语言代码、地区代码及同一站点下的 URL 前缀必须进行冲突校验。
- 系统必须支持 LTR 与 RTL；阿拉伯语和希伯来语启用时能够绑定独立 RTL 模板。

## 7.4 内容模型管理

### 功能要求

- 支持创建文章、产品资料、专题、落地页、单页等内容模型。
- 支持新增文本、长文本、富文本、数字、日期、开关、单选、多选、媒体、文件、关联内容、结构化列表等字段。
- 字段可以设置是否必填、默认值、唯一性、验证规则、字符长度和帮助说明。
- 字段可以设置为全局共享或按语言独立。
- 字段可以设置为可搜索、可筛选、可排序、可用于 SEO 或不可公开。
- 内容模型支持版本管理，修改字段时必须进行兼容性和数据影响检查。
- 已经存在数据的字段不得直接无提示删除。
- 支持内容模型导出和导入，便于站点之间迁移。

### 大数据规则

- 内容 ID 应使用足够大的数值范围或稳定唯一标识，避免后期容量不足。
- 正文等大字段应与高频列表字段分离存储或分离读取。
- 列表页不得默认加载正文、完整修订历史或全部媒体信息。
- 自定义字段必须有可控的索引策略，不能允许管理员无上限创建数据库索引。

## 7.5 内容管理与编辑

### 基本功能

- 创建、编辑、复制、预览、审核、发布、定时发布、下线、归档和恢复内容。
- 支持自动保存、手动保存和未保存离开提醒。
- 支持内容版本历史、版本对比和一键回滚。
- 支持批量修改栏目、标签、状态和发布时间。
- 支持内容负责人、审核人和复审日期。
- 支持内容有效期和过期提醒。
- 支持关联内容、相关文章和手工内链。
- 支持软删除和回收站。
- 永久删除属于高风险操作，必须具备权限、二次确认和审计记录。

### 多语言编辑

- 内容详情页以语言标签或语言列表展示各版本。
- 每个语言版本独立保存以下字段：
  - 标题；
  - Slug；
  - 摘要；
  - 正文；
  - 图片 Alt；
  - 标签；
  - SEO 标题；
  - SEO 描述；
  - Canonical 特殊覆盖；
  - 页面布局配置；
  - 发布状态；
  - 发布时间。
- 不同语言版本通过内容组关联。
- 原始版本更新后，其他语言版本应标记为“需要检查”或“本土化内容可能过期”，但不得自动覆盖人工内容。
- 支持显示不同语言的完成度和最后更新时间。
- 支持设置某个语言版本为本土化参考源。
- 支持对目标语言版本发起“AI 本土化重写”，该功能不是逐句翻译功能。
- AI 应读取完整源页面语境、页面类型、目标受众、国家市场、Locale、品牌词典、禁用词和目标搜索意图后重新组织目标语言内容。
- 本土化版本允许与源版本采用不同的标题、段落组织、表达方式、关键词布局和行动号召，但不得改变可验证事实、产品参数、品牌含义、价格货币事实、物流承诺或法律合规声明。
- 源版本更新时，只把受影响的目标语言版本或内容块标记为“需要重新本土化”，不得直接覆盖已由人工编辑或审核通过的内容。
- 人工编辑过的字段可设置为“人工锁定”；任何 AI 批量同步均不得修改这些字段。

### 内容状态

至少包含：

```text
草稿
待本土化
本土化处理中
待审核
审核退回
审核通过
待发布
已发布
需要更新
已下线
已归档
```

### 发布规则

- 草稿、预览、审核退回内容不得出现在公开 Sitemap。
- 未发布页面的预览地址必须鉴权或使用短期签名，并输出 `noindex`。
- 已发布内容修改后，可根据站点规则选择立即更新或重新进入审核流程。
- 内容发布必须触发页面更新、缓存刷新、搜索索引更新、Sitemap 更新和相关页面依赖更新。

## 7.6 栏目、菜单与标签

### 功能要求

- 栏目支持多级树结构、排序、移动和批量操作。
- 栏目名称、Slug、描述和 SEO 按语言独立维护；栏目页面使用该语言当前生效模板套装内的栏目页模板。
- 栏目内部 ID 不因移动或改名而变化。
- 栏目移动前显示受影响内容和 URL 数量。
- 菜单与栏目分离，同一内容可以出现在不同菜单中。
- 菜单文字、链接和层级按语言管理。
- 标签支持多语言名称、别名、合并和重定向。
- 系统应防止产生无限层级或栏目循环引用。

## 7.7 主题与模板管理

### 目标

系统可以安装和保存多套模板。每个“站点 + 语言”必须独立选择一套当前生效的完整模板套装，并保证模板变更安全、可预览、可切换、可回滚。

### 主题功能

- 上传、安装、启用、停用、复制和卸载模板套装。
- 显示主题名称、版本、作者、兼容 CMS 版本和依赖。
- 主题包含明确清单文件，声明页面模板、组件、静态资源和可配置项。
- 主题支持版本管理，不允许直接无记录覆盖生产版本。
- 主题发布前支持桌面端和移动端预览。
- 模板切换必须采用原子发布：校验通过后一次性把该语言指向新模板版本，失败时继续使用旧版本。
- 支持快速回滚到上一完整模板版本。
- 正在被站点或语言使用的主题不得直接删除。
- 系统可同时安装任意多套兼容模板，但一套模板必须完整包含其声明支持的页面类型。
- 模板套装应支持复制为新的独立模板，复制后修改不得影响原模板。

### 按语言绑定模板

- 模板绑定的最小业务单位为“站点 + 语言”。
- 同一站点下，每种已启用语言必须绑定一套完整模板套装后才能正式发布。
- 同一种语言在生产环境中只能存在一个当前生效模板套装。
- 每种语言可以保留多个未生效候选模板、草稿版本和历史版本。
- 模板套装内部必须包含首页、栏目页、列表页、内容页、专题页、搜索页、404 页等所需页面模板。
- 语言页面不能在生产环境中跨多个主题随意选择页面模板，避免样式、组件和资源依赖混乱。
- 切换语言模板时应以整套模板为单位完成预览、校验、发布和回滚。
- 英语、德语、法语等语言可以分别绑定完全不同的模板套装。
- 如多个语言需要使用相同设计，可以分别绑定同一模板的独立配置实例；各语言的词典、导航、组件配置和版本状态互不覆盖。
- 新增语言后，管理员可以选择一套现有模板作为基础，复制为该语言的独立模板实例，再修改语言词典和布局配置。
- 内容和栏目不得绕过语言模板绑定直接使用其他语言的生产模板。

示例：

```text
英语 en-GB   → Europe-English V3（当前生效）
德语 de-DE   → Germany-Modern V2（当前生效）
法语 fr-FR   → France-Brand V1（当前生效）
西班牙语 es-ES → Spain-Light V1（当前生效）
意大利语 it-IT → Italy-Editorial V4（当前生效）
荷兰语 nl-NL  → Netherlands-Clean V2（当前生效）
```

### 模板切换流程

1. 为指定语言选择已安装模板或复制现有模板；
2. 创建该语言的候选模板实例；
3. 补齐模板语言词典、导航、页头、页脚和组件配置；
4. 预览首页、栏目页、内容页、搜索页和错误页；
5. 执行兼容性、缺失词条、SEO、链接和性能检查；
6. 发布后将候选模板标记为当前生效模板；
7. 刷新该语言相关页面和缓存；
8. 保留原模板版本，出现问题时可以整套回滚。

### 模板语言词典

- 主题中的按钮、提示、导航固定文案不能直接写死。
- 每个主题提供语言词典管理。
- 新增语言时显示缺失词条、完成率和回退结果。
- 缺失词条在生产发布前应有警告。

### 模板安全

- 后台模板不应默认允许执行任意系统命令或任意服务端代码。
- 模板只能访问经过授权的内容字段、组件数据和帮助函数。
- 模板上传应检查路径穿越、危险文件、脚本和不允许的依赖。
- 模板变更必须记录操作者、时间、版本和变更说明。

### 模板性能

- 模板应支持静态资源合并、压缩、版本化和 CDN。
- 模板必须支持响应式布局和移动端优先。
- 首屏图片、字体和第三方脚本需要性能约束。

## 7.8 URL 与伪静态管理

### 目标

为不同站点、语言和内容模型提供可配置、稳定、可追踪的 URL 规则。

### URL 规则

系统至少支持以下变量：

```text
{language}
{locale}
{category}
{category_path}
{slug}
{id}
{year}
{month}
{day}
{page}
```

支持的示例：

```text
/{language}/{category}/{slug}.html
/{language}/{slug}/
/{category_path}/{id}.html
/{language}/{year}/{month}/{slug}.html
```

### 功能要求

- 每个站点、语言和内容类型可以配置 URL 规则。
- 支持是否带语言前缀、是否带 `.html`、是否保留末尾斜杠。
- 支持 Slug 手工填写、从标题生成、拉丁化或拼音化。
- 支持统一小写、非法字符清理和保留字符限制。
- 支持保留路径管理，例如 `/admin`、`/api`、`/login`。
- URL 发布前进行唯一性和路由冲突检查。
- 修改内容 Slug、栏目或规则时保存完整 URL 历史。
- 支持自动建议或创建 301 重定向。
- 支持手工创建 301、302、410 规则。
- 支持重定向链和循环检测。
- 支持 URL 规则变更预演，显示预计变化、冲突和重定向数量。
- 批量变更采用后台任务，支持进度、失败重试和回滚计划。

### 业务规则

- 伪静态只是路由表现，速度优化必须依赖页面缓存、静态生成和 CDN。
- URL 不能作为内容数据库主键。
- 已发布 URL 的改变必须保留历史记录。
- 相同内容语言版本只能有一个主要规范 URL。
- 分页、筛选和参数页面必须有统一的 Canonical 与收录策略。

### 验收要求

- 管理员可以不改代码地配置 `.html` 或目录风格 URL。
- 十万级 URL 规则变更应通过队列执行，不能阻塞后台请求。
- 系统能够检测重复 Slug、重复路径、循环跳转和失效目标。

## 7.9 SEO 中心

### 7.9.1 页面级 SEO

每个语言版本支持：

- SEO 标题；
- Meta Description；
- H1；
- Slug；
- Canonical；
- `index/noindex`；
- `follow/nofollow`；
- Open Graph；
- 社交分享图片；
- 图片 Alt；
- 结构化数据；
- 面包屑；
- 关键词规划字段。

说明：关键词字段用于内部内容规划、页面映射和冲突检查。系统默认不输出 `meta keywords`，也不提供关键词密度或关键词堆砌功能。

### 7.9.2 多语言 SEO

- 自动为真实存在且已发布的对应语言页生成 `hreflang`。
- `hreflang` 必须支持自引用和双向对应。
- 支持配置 `x-default`。
- 未发布、被禁止收录或不存在的语言版本不得进入 `hreflang` 集合。
- 每种语言页面默认指向自身 Canonical，除非 SEO 人员明确覆盖。
- 系统应检查语言代码、目标 URL、返回状态和双向关系。

### 7.9.3 Sitemap

- 支持 Sitemap Index。
- 按站点、语言、内容类型或时间拆分 Sitemap。
- 单文件接近 50,000 URL 或 50MB 未压缩上限前自动拆分，建议内部采用更保守阈值。
- 仅输出规范、可索引、返回成功状态的 URL。
- 内容发布、下线和 URL 修改后增量更新。
- 支持图片 Sitemap 扩展或独立媒体 Sitemap，视内容类型启用。

### 7.9.4 robots.txt

- 每个站点独立管理 robots.txt。
- 提供默认安全模板。
- 检测误屏蔽全站、静态资源或重要页面的危险规则。
- robots.txt 修改需要预览、权限控制和审计。
- robots.txt 不用于保护敏感数据；敏感页面必须鉴权。

### 7.9.5 结构化数据

- 使用 JSON-LD 输出。
- 支持 Organization、WebSite、BreadcrumbList、Article 等基础类型。
- 后续根据内容模型扩展 Product、FAQ 等类型，但必须符合对应 Google 展示资格要求。
- 模板配置不得编造评分、价格、库存、作者或其他不存在的数据。
- 发布前进行字段完整性和 JSON 格式检查。

### 7.9.6 SEO 检查

- 重复标题和描述；
- 标题、描述缺失；
- 多个 H1 或缺失 H1；
- 重复正文；
- 失效 Canonical；
- 错误 `hreflang`；
- 断链和重定向链；
- 孤立页面；
- 薄内容提示；
- 图片缺少 Alt；
- 可索引页面被 robots 屏蔽；
- 草稿或预览页面被收录风险；
- 多个页面目标关键词冲突。

SEO 检查只表示技术规范检查结果，系统不得宣称能够保证 Google 排名或收录。

### 7.9.7 关键词规划中心

- 关键词用于内部SEO规划，不默认输出为 `meta keywords`。
- 关键词按站点、国家市场、语言地区版本和搜索意图管理。
- 支持主关键词、次关键词、同义词、相关实体词、问题词和禁用词。
- 搜索意图至少分为信息型、商业调查型、交易型和导航型。
- 每个目标关键词可以绑定一个主要落地页，并显示该页面的标题、H1、Slug、摘要、正文模块、图片Alt和内链覆盖情况。
- 同一市场中多个可索引页面目标关键词高度重复时产生内容蚕食提示。
- 不同语言的关键词是独立研究结果，系统不得把中文关键词机械直译后视为已经完成本土化。
- 支持关键词分组、主题集群、负责人、状态和备注。
- 接入Search Console后，可关联查询词、曝光、点击、CTR、排名和对应页面。
- 关键词布局检查只提供编辑建议，不设置机械密度标准，不鼓励关键词堆砌。

### 7.9.8 多站点多语言独立 SEO 与继承规则

- SEO 配置范围按“全局默认 → 站点 → 国家市场与 Locale → 内容类型或模板 → 单个页面”五级管理。
- 下一级可继承上一级默认值，也可独立覆盖；单个页面的明确设置优先级最高。
- 每个 `Site + Market + Locale + Page` 组合均可拥有独立 SEO 标题、Meta Description、H1、Slug、Canonical、收录状态、Open Graph、图片 Alt、关键词方案、结构化数据和内链策略。
- 同一种语言面向不同国家时，可分别设置关键词和 SEO，例如 `en-US`、`en-GB`、`en-AU` 不共用被写死的关键词方案。
- 每个站点独立管理 robots.txt、Sitemap/Sitemap Index、Canonical 域名规则和 Search Console 连接；每个已发布语言版本进入自己所属站点和 Locale 的 Sitemap。
- `hreflang` 只连接真实存在、已发布、可索引且语义对应的地区语言页面；不得为了凑齐语言列表生成空页面或错误对应关系。
- 系统必须显示每个 SEO 字段的最终值、来源层级和覆盖状态，避免继承关系不可追踪。
- AI 可以为各站点和地区版本提出独立 SEO 方案，但人工锁定值和页面级人工覆盖值优先，AI 不得强制替换。

## 7.10 媒体中心

### 功能要求

- 图片、视频、文档和其他附件统一管理。
- 文件实际内容存储到对象存储或独立文件存储，不建议全部写入关系数据库。
- 支持文件夹、标签、搜索、批量操作和引用关系查看。
- 显示一个文件被哪些内容、语言和模板使用。
- 支持按语言填写 Alt、标题、说明和版权信息。
- 自动读取图片尺寸、格式和文件大小。
- 自动生成缩略图和响应式尺寸。
- 支持 WebP、AVIF 等现代格式。
- 支持图片质量、裁切焦点和尺寸预设。
- 替换文件时保留历史和引用关系。
- 删除被引用文件时必须阻止或明确提示影响范围。

### 安全要求

- 校验扩展名、MIME 类型和文件实际内容。
- 设置单文件大小、总容量和用户配额。
- 拒绝危险可执行文件和双扩展名欺骗。
- 图片可重新编码，附件可接入病毒扫描。
- 上传后的文件不应直接获得服务端执行权限。
- 文件名与对象存储路径由系统生成，避免路径穿越和覆盖。

## 7.11 发布与页面交付

### 架构要求

前台公开访问不应在每次请求中完整执行后台内容查询和模板拼装。系统应支持以下一种或多种方式组合：

- 服务端渲染并缓存；
- 页面静态生成；
- 增量静态再生成；
- CDN 边缘缓存；
- 动态 API 仅用于搜索、筛选或必须实时的区域。

### 发布功能

- 单页发布、批量发布、定时发布和全站构建。
- 只重新生成受影响页面，避免每次全站重建。
- 维护内容与栏目、菜单、模板、相关推荐之间的依赖关系。
- 发布任务支持队列、优先级、并发限制、超时和自动重试。
- 相同发布请求应具备幂等性，重复执行不能产生重复记录。
- 显示任务进度、成功数量、失败数量和错误原因。
- 支持发布前预览和发布后自动验证页面状态。
- 支持回滚到上一内容版本或上一模板版本。
- CMS 后台短暂不可用时，已发布且已缓存页面应继续提供服务。

### 缓存刷新

- 支持按页面、内容、栏目、语言、站点和标签清理缓存。
- 内容修改时只清理直接页面和相关依赖页面。
- 避免全量缓存同时过期。
- 支持热门页面预热。
- 缓存刷新失败应进入重试队列并产生告警。

## 7.12 性能与缓存中心

### 缓存层级

- 浏览器缓存；
- CDN 缓存；
- 整页缓存；
- 模板片段缓存；
- Redis 数据缓存；
- 数据库查询结果缓存；
- 搜索结果短期缓存。

### 管理功能

- 查看缓存命中率、对象数量、占用空间和失效情况。
- 按范围清理缓存，不默认提供无提示的全量清理。
- 支持缓存预热任务。
- 支持缓存键版本化。
- 防止缓存击穿、穿透和雪崩。
- 管理员执行全站清理时必须提示可能产生的源站压力。

### 性能目标

以下为建议验收目标，最终应结合服务器配置、数据规模和并发模型确定：

- 已命中 CDN 的公开页面 P95 TTFB 不高于 200ms；
- 未命中 CDN 但命中页面缓存的请求 P95 TTFB 不高于 500ms；
- 必须动态渲染的普通页面 P95 TTFB 不高于 800ms；
- Google Core Web Vitals 第 75 百分位目标：LCP 不高于 2.5 秒、INP 不高于 200ms、CLS 不高于 0.1；
- 缓存预热后的公开可缓存页面 CDN 命中率目标不低于 90%；
- 普通单页内容发布在无队列积压时应在 60 秒内完成前台更新。

性能数据必须区分缓存命中、未命中、设备、地区和页面类型，不能只展示平均值。

## 7.13 大数据存储与查询

### 数据分类

| 数据类型 | 建议职责 |
|---|---|
| SQLite 主数据库 | 用户、权限、站点、内容元数据、版本、SEO、发布状态和审计记录 |
| 正文与扩展字段 | 根据访问模式分离读取，避免拖慢列表查询 |
| 对象存储 | 图片、视频、附件、导出文件 |
| Go 进程内存 | L1 热数据缓存；可丢弃、可重建，不保存唯一数据 |
| Redis（可选） | L2 共享缓存、限流、会话、锁、任务状态和缓存失效通知 |
| SQLite FTS5 | 第一阶段全文搜索；按 Locale 分词或规范化，复杂多语言检索保留外部搜索接口 |
| SQLite 任务表 + Go Worker Pool | 发布、索引、图片处理、批量导入和通知；任务必须持久化、幂等、可重试 |
| 分析存储 | 浏览量、访问事件、性能与日志数据 |

### 功能要求

- 支持百万级内容记录的渐进扩展，不在业务代码中设置不合理的低容量硬限制。
- SQLite 容量验收必须分别覆盖 100 万和 1,000 万内容元数据记录的索引、分页、发布和备份场景；能否达到正式目标以真实硬件压测为准，不以数据库文件能写入为通过标准。
- 使用适合查询模式的联合索引，并提供索引使用和慢查询监控。
- 大数据列表使用游标分页或搜索引擎翻页，避免无限制深度 Offset。
- 计数采用汇总或异步统计，避免频繁执行全表 `COUNT`。
- 浏览量和访问事件异步聚合，不在每次请求中更新内容主表。
- 支持按站点、时间或内容类型进行分区与归档。
- SQLite 单库只允许一个并发写事务；应用必须采用短事务、有界写任务、批量提交和 `busy_timeout`，不得在事务中调用 AI、网络或文件处理。
- 达到预设写延迟、锁等待、数据库文件体积或备份窗口阈值时，应按站点归档/拆库或通过仓储接口迁移 PostgreSQL，不能用无限重试掩盖瓶颈。
- 支持冷热数据分层。
- 支持数据库读副本，但写入一致性必须有明确规则。
- 支持批量任务断点续传和失败记录。
- 搜索索引必须能够从主数据重新构建。
- 所有数据结构变更应有迁移版本、执行记录和回滚或前滚方案。

### 压测场景

技术方案确定后至少测试：

- 千万级内容下按站点和语言读取详情；
- 按栏目、状态、时间排序的后台列表；
- 多语言全文搜索；
- 批量导入和批量发布；
- 高并发缓存命中与缓存未命中；
- 大规模 URL 规则变更；
- 搜索索引全量重建；
- 数据备份和恢复耗时。

## 7.14 搜索管理

### 功能要求

- 后台内容全文搜索。
- 前台按站点和语言隔离的全文搜索。
- 支持不同语言的分词器、同义词和停用词。
- 支持标题、摘要、正文、标签和自定义字段权重。
- 支持按栏目、内容类型、语言、发布时间等筛选。
- 支持拼写纠正、搜索建议和无结果词统计，作为增强功能。
- 内容发布、修改和删除后增量更新索引。
- 提供全量重建索引、索引切换和失败回滚。
- 搜索服务故障时，前台应有降级结果或友好提示，不得拖垮主数据库。

## 7.15 数据导入导出

### 功能要求

- 支持 CSV、Excel 或标准 JSON 的批量导入导出。
- 支持字段映射、语言映射、栏目映射和数据预览。
- 导入前检查必填字段、重复 Slug、非法 URL 和语言代码。
- 大文件导入必须使用后台任务，支持进度和断点续传。
- 每条失败数据记录明确错误原因，可单独修复重试。
- 支持只新增、存在则更新和完全覆盖三种策略。
- 完全覆盖属于高风险操作，必须确认并生成备份或回滚点。
- 导出必须受权限约束，并记录导出人、范围和时间。
- 含敏感字段的数据默认禁止普通编辑人员导出。

## 7.16 API、Webhook 与扩展机制

### API 要求

- API 版本化，避免升级导致已有集成突然失效。
- 支持按站点、语言和资源范围授权。
- 支持访问令牌过期、撤销和轮换。
- 支持请求限流、分页、排序和标准错误格式。
- 写入接口支持幂等键。
- 重要 API 操作写入审计日志。
- API 文档应由接口定义自动生成或同步维护。

### Webhook 要求

- 支持内容创建、更新、审核、发布、下线和删除等事件。
- Webhook 使用签名、时间戳和重放防护。
- 支持失败重试、最大次数和死信记录。
- 管理员可以查看每次投递的状态，但敏感请求内容应脱敏。

### 扩展机制

- 内容模型、自定义字段、模板组件和事件 Hook 是第一阶段扩展重点。
- 后续插件必须声明所需权限，不能默认获得数据库、文件系统和系统命令权限。
- 插件应具备版本、兼容范围、启停、升级和卸载记录。
- 第一版不要求建设公开插件市场。

## 7.17 用户、登录与权限安全

### 账号安全

- 管理员支持 MFA，优先支持 TOTP，并为未来 Passkey 预留。
- 密码使用现代安全哈希算法存储，禁止明文和可逆加密。
- 支持密码强度、过期策略和泄露密码检查扩展。
- 登录失败限速、验证码策略和短期锁定。
- 支持会话查看、单个设备退出和全部会话撤销。
- 支持闲置超时和绝对会话有效期。
- 关键账号变更、MFA 关闭和权限提升必须二次验证。

### 应用安全

- 防止 SQL 注入、XSS、CSRF、SSRF、路径穿越、命令注入和不安全反序列化。
- 所有数据库查询使用安全参数化方式。
- 富文本输出必须经过允许列表过滤和上下文编码。
- 后台接口进行权限校验，不能只隐藏前端按钮。
- 使用安全响应头，包括合理的 CSP、HSTS、X-Content-Type-Options 等。
- 管理后台与公开前台可使用独立域名或独立入口。
- API、登录、搜索和上传接口配置独立限流规则。

### 密钥与依赖

- 数据库密码、API 密钥等不得写入代码仓库。
- 支持密钥轮换和不同环境独立密钥。
- 建立依赖清单和漏洞扫描。
- 高危漏洞需要有修复时限和升级记录。

## 7.18 审计日志

### 必须审计的操作

- 登录、退出、登录失败和 MFA 变更；
- 用户、角色和权限变更；
- 内容审核、发布、下线、回滚和永久删除；
- 语言新增、停用和删除；
- 模板安装、发布、回滚和删除；
- URL 规则、重定向、Canonical、robots.txt 和 Sitemap 配置变更；
- API Token 创建、撤销和权限变更；
- 数据导入、导出、备份和恢复；
- 缓存全量清理和生产环境配置变更。

### 日志字段

- 操作人；
- 时间；
- 来源 IP 与设备信息；
- 站点和语言范围；
- 操作类型；
- 对象 ID；
- 修改前后摘要；
- 结果和失败原因；
- 关联任务 ID。

审计日志普通管理员不得修改或删除。日志保留期限应可配置，并支持导出到外部日志系统。

## 7.19 任务中心

## 7.22 公开前台访问与页面展示

### 页面类型

- 首页；
- 栏目页和列表页；
- 内容详情页；
- 专题或落地页；
- 搜索页；
- 标签页；
- 404、410、500 和维护提示页；
- robots.txt、Sitemap 和站点必要机器可读文件。

### 多语言展示

- 每个公开页面必须使用当前“站点 + 语言”绑定的唯一生效模板套装。
- 语言切换器只显示该站点已启用的语言。
- 当前内容存在已发布对应语言版本时，切换器直接进入对应内容页。
- 对应语言内容不存在时，可选择不显示该语言链接，或跳转该语言首页；不得伪造不存在的对应页 `hreflang`。
- URL、导航、栏目、面包屑、固定界面文案和日期数字格式必须与当前语言一致。
- RTL 语言启用时，页面方向、导航、图标顺序和主要组件应正确镜像或适配。

### HTTP 与页面规则

- 正常规范页面返回 200。
- 永久移动返回 301，临时跳转返回 302，永久删除可返回 410，不存在页面返回真实 404。
- 不允许所有错误页面统一返回 200。
- Canonical、`hreflang`、结构化数据和语言切换链接必须使用最终规范 URL。
- 预览页需要鉴权或短期签名，并输出 `noindex`。
- 维护模式应区分后台维护和前台维护；前台临时不可用时返回合适状态并可配置 `Retry-After`。
- 公开页面不得加载后台专用脚本、后台会话信息或敏感配置。

### 交互与可用性

- 支持桌面、平板和移动端响应式显示。
- 核心导航和内容在 JavaScript 失败时仍应具备基本可访问性。
- 图片提供尺寸、懒加载策略和响应式资源；首屏关键图片不得错误延迟加载。
- 页面支持键盘操作、合理标题层级、Alt、表单标签和基础色彩对比度。
- 搜索和筛选参数必须进行输入验证、限流和收录控制。
- 404 页面提供返回首页、主要栏目和站内搜索入口，但不得将所有 404 强制跳转首页。

### 验收要求

- 六种首批语言可分别使用完全不同的模板正常访问。
- 页面返回状态、Canonical、`hreflang` 和 Sitemap 记录相互一致。
- 已停用语言不能通过旧语言切换入口生成新的公开页面。
- 在后台短暂不可用时，已经发布并缓存的公开页面仍能继续访问。

## 7.23 系统配置与生命周期管理

### 配置中心

- 配置按系统、环境、站点、语言和模块分组。
- 每项配置具有类型、默认值、说明、验证规则、敏感级别和生效范围。
- 敏感配置只显示脱敏结果，不允许通过普通配置导出泄露。
- 生产配置变更保留修改前后、操作人、时间和变更原因。
- 支持配置预览和生效检查，危险配置需要二次确认。
- 开发、测试、预发布和生产配置相互隔离。
- 环境变量和Secret Manager中的密钥不能被数据库普通配置覆盖为明文。

### 系统状态

- 支持正常、维护、只读和发布冻结状态。
- 只读状态允许访问内容但阻止内容写入。
- 发布冻结只阻止生产发布，不影响草稿编辑。
- 紧急模式可撤销API Token、强制管理员重新登录和暂停外部Webhook。
- 系统状态改变必须有权限限制、二次确认和审计。

### 安装与升级

- 部署前检查 Go 应用版本、SQLite 文件与目录权限、迁移、磁盘空间、内存缓存、可选 Redis 和媒体存储连接。
- 数据库结构通过版本化迁移管理，禁止手工无记录修改生产表结构。
- 升级前执行兼容性、磁盘空间、队列积压和备份状态检查。
- 数据库迁移采用可回退或可前滚方案；大表修改采用低锁或分阶段策略。
- 发布后通过 Go HTTP Server 优雅关闭等待在途请求，并安全停止 Worker Pool；未完成的持久化任务由新实例继续领取。
- 系统显示当前应用版本、数据库迁移版本、模板兼容版本和最近升级时间。
- 升级失败必须保留旧应用版本和恢复路径。

## 7.28 AI 语境本土化、内容同步与 SEO 重写

### 7.28.1 定位与强制原则

- 本模块的正式名称为“AI 本土化重写”，不是“机器直译”。
- 用户要求的“100% 根据语境改写”是指全部 AI 输出必须走语境、本土市场和搜索意图分析流程，不允许把逐句翻译结果直接当作完成内容；该表述不代表系统承诺 100% 准确、收录或排名。
- 每次任务必须明确源内容、目标站点、目标国家市场、目标语言、目标 Locale、受众、页面类型和业务目标。
- AI 必须先理解完整页面语义和上下文，再按照当地自然表达重写；不得按句子一一对应，也不得强制保持与源页面完全相同的段落结构。
- 输出应像目标国家的本地编辑撰写，避免翻译腔、中文语序、无当地搜索价值的直译词和关键词堆砌。
- AI 只能在原始事实和已授权素材范围内重写，不得虚构产品能力、认证、客户、价格、时效、服务地区、评价、统计数据或 Google 排名保证。

### 7.28.2 目标市场关键词本土化

- 关键词研究范围必须绑定 `Site + Market + Locale + Search Intent`，不能只绑定语言。
- AI 应根据当地用户实际表达、同义词、行业术语、拼写差异、单复数、地区词、搜索意图和页面用途生成候选关键词。
- 德语、法语、西班牙语、英语等跨多个国家使用的语言，必须允许不同国家拥有不同关键词组合、标题和内容布局。
- AI 可结合已导入或已授权的 Search Console、关键词工具、站内搜索词和历史表现数据优化候选方案；没有真实搜索量数据时必须标注为“AI 建议”，不得伪造搜索量、竞争度或排名数据。
- 每个目标页面应输出主关键词、次关键词、相关实体词、问题词、搜索意图、推荐落点和内容蚕食风险。
- 关键词应自然布局于 SEO 标题、H1、摘要、正文模块、图片 Alt、Slug 和内链锚文本中；不采用固定关键词密度，不为堆词破坏可读性。
- 品牌词、型号、技术参数、法规名称及其他不可翻译词由术语库控制，支持按站点、市场和 Locale 覆盖。

### 7.28.3 可生成和重写的内容字段

AI 任务可按权限和规则处理：

- 页面标题与 H1；
- SEO 标题与 Meta Description；
- 主关键词、次关键词、相关词和搜索意图；
- Slug 候选及旧 URL 重定向建议；
- 摘要、正文、FAQ 和模板内容模块；
- 图片 Alt、图片说明和文件语义标签；
- 内链目标与锚文本建议；
- Open Graph 标题与描述；
- 仅基于真实字段生成的结构化数据文本部分；
- 本土化行动号召、单位、日期格式和地区表达。

### 7.28.4 同步模式与任务流程

支持三种同步模式：

1. 全页面本土化：为尚无目标版本的页面创建完整草稿。
2. 变更块同步：只分析源版本变动的内容块，并标记目标版本受影响范围。
3. 选定字段同步：管理员只选择标题、SEO、正文、Alt 或指定模块执行。

目标语言不在代码中写死，由当前“已上线分站模板”动态决定。一个目标只有同时满足以下条件才会自动加入同步：站点状态为运行中、语言与 Locale 已启用、当前绑定模板已通过安全验证且能够完成前台渲染、操作者拥有目标站点/Locale 的内容与 SEO 权限。维护中或已停用的站点、停用语言、未绑定模板和不可渲染模板不得接收 AI 版本。新语言分站完成上述上线配置后，无需修改程序即可自动出现在同步目标中。

标准流程如下：

```text
选择源版本与目标市场/Locale
→ 检测源内容和变更块
→ 加载品牌规则、术语库、禁用词与关键词数据
→ 创建各目标版本的异步任务
→ AI 进行语境本土化重写和地区 SEO 规划
→ 执行事实、术语、SEO、URL、重复内容和合规检查
→ 展示逐字段/逐内容块差异
→ 人工修改与审核
→ 审核通过后进入正常发布工作流
```

- 源内容更新只改变同步状态并产生建议，不得直接替换已发布目标版本。
- 发起全页面本土化时，后台默认选中全部已上线且尚无目标内容版本的分站；已有版本只显示状态并跳过，绝不自动覆盖。
- 批量任务按目标站点、市场和 Locale 分开排队，支持进度、暂停、取消、幂等、限速、失败重试和死信处理。
- 可按站点和语言配置自动发起任务，但默认输出仍为草稿；第一版不得默认无人审核自动发布。
- 每个目标版本保留源版本号、最后同步版本、差异状态、审核状态和发布时间，能够识别“已同步”“源内容已更新”“人工偏离”“等待审核”等状态。

### 7.28.5 字段控制、人工审核与回滚

每个可重写字段至少具有以下控制模式：

- 人工锁定：AI 只可读取上下文，不可修改该字段；
- AI 建议：生成候选值，由人工选择是否采用；
- AI 管理：允许后续 AI 任务更新，但结果仍须遵守站点发布审批规则。

系统还必须：

- 默认把人工输入和已审核字段视为高优先级，不因批量任务被静默覆盖；
- 在采用前显示原值、AI 候选值、差异、关键词变化、删除内容和风险提示；
- 支持逐字段采用、整页采用、驳回、重新生成和人工编辑；
- 保存源版本、每次 AI 生成版本、人工修改版本和最终发布版本，并可随时比较与回滚；
- 记录操作人、审核人、时间、AI 提供方、模型、提示模板版本、参数、输入输出摘要、Token/费用、任务状态和失败原因；
- 不把未审核 AI 内容写入公开页面、Sitemap、`hreflang` 或搜索索引。

### 7.28.6 AI 安全、质量与成本控制

- CMS 核心通过提供方无关的 AI 适配层调用模型，不把业务数据结构绑定到单一 AI 厂商。
- AI API 密钥进入密钥管理系统，不写入代码、模板、日志或普通数据库配置页面。
- 对发往外部 AI 的内容进行权限、敏感数据和发布状态检查；未授权私有数据、询盘个人信息和密钥不得进入提示词。
- 把页面中的第三方文本视为不可信内容，防止内容内指令、提示注入或隐藏文本改变系统规则。
- AI 输出必须经过类型、长度、Locale、HTML、URL、危险内容、事实字段、术语和结构化数据校验。
- 支持按用户、站点、市场、任务类型和时间周期设置次数、Token、并发与费用上限，达到阈值后暂停并告警。
- 支持超时、重试、熔断、降级和提供方切换；失败不得阻塞正常人工编辑和网站公开访问。
- 可配置 AI 提供方的数据保留策略，并在审计记录中标明数据发送范围。

### 7.28.7 验收要求

- 同一源页面可分别为不同国家和 Locale 生成明显符合当地表达的独立草稿，而不是逐句对应的直译稿。
- AI 能分别生成本土化标题、SEO 标题、描述、关键词、Slug、正文、Alt 和内链建议。
- 同一种语言面向不同国家时，可以生成并保存不同的关键词方案和内容结构。
- 人工锁定字段在单次和批量 AI 同步中均保持完全不变。
- 源版本更新后，目标版本正确标记为需要检查，并保留已经发布和人工编辑的内容。
- 未经人工审核的 AI 内容默认不可发布，也不进入 Sitemap、`hreflang` 和公开搜索索引。
- 管理员可以查看逐字段差异、采用或驳回候选、追踪完整生成记录并回滚。
- AI 任务失败可安全重试且不会生成重复版本；额度、成本和异常均可查询与告警。

## 9. 非功能需求

## 9.1 可用性

- 已发布前台与后台管理服务解耦，后台故障不应立即导致所有前台页面不可访问。
- 关键依赖故障应有降级策略。
- 所有异步任务应可定位、重试和告警。

## 9.2 可扩展性

- 新增语言不修改核心代码。
- 新增内容类型通过后台模型配置完成。
- 新增主题通过标准主题包完成。
- API、事件和 Webhook 有版本管理。
- 数据、缓存、搜索和媒体服务可以独立扩容。

## 9.3 可维护性

- 模块边界清晰，禁止跨模块随意直接修改数据。
- 配置有默认值、说明、验证和变更历史。
- 数据库变更必须通过版本化迁移。
- 关键功能具有自动化测试和回归测试。

## 9.4 兼容性

- 后台优先支持当前稳定版本的 Chrome、Edge。
- 前台支持主流现代浏览器和移动设备。
- 全站采用 UTF-8，预留非拉丁文字和 RTL 语言。
- 前台模板符合响应式和移动端优先原则。

## 9.5 隐私与合规

- 日志和导出中对令牌、密码、密钥等敏感信息脱敏。
- 提供数据保留期配置。
- 为以后欧洲隐私、Cookie 同意和数据删除请求预留接口。
- 隐私合规页面按语言和站点独立管理。

## 12. 第一版整体验收清单

### 多语言

- 安装后语言库包含文档规定的 24 种预置语言，默认只启用首批六种。
- 未启用的预置语言不生成前台入口、URL、Sitemap、`hreflang` 或空内容页。
- 可在中文后台直接启用任一预置语言，也可新增预置库之外的第 25 种及更多语言，均无需修改代码。
- 新语言可配置 Locale、URL 前缀、回退语言和模板。
- 可为新语言创建独立内容、栏目、菜单和 SEO。
- 繁体中文可按站点选择 `zh-HK`、`zh-TW` 等地区 Locale；葡萄牙语等语言也可选择对应国家 Locale。
- 阿拉伯语、希伯来语等 RTL 语言启用时，系统和模板能够正确切换文字方向。
- 未发布语言页不会进入 Sitemap 和 `hreflang`。
- 停用语言前显示影响范围，并保留历史 URL 处理能力。
- 可按源页面、目标站点、国家市场和 Locale 创建 AI 本土化草稿，正式流程不采用逐句机械直译。

### 模板

- 系统能够同时安装和管理多套模板。
- 同一站点下每种已启用语言分别具有唯一的当前生效模板绑定。
- 不同语言可以使用完全不同的模板套装。
- 多个语言使用相同设计时，也应具有相互隔离的语言配置实例。
- 一套模板完整包含首页、栏目页、列表页、内容页、搜索页和 404 页等所需页面。
- 模板切换按整套执行，不允许产生一半新模板、一半旧模板的线上状态。
- 主题词典可按语言编辑并检查缺失项。
- 模板可预览、版本化和整套回滚。
- 模板不能默认执行任意服务端代码。

### URL

- 可通过后台切换目录风格和 `.html` 风格 URL。
- URL 规则支持语言、栏目、Slug、ID 和日期变量。
- 修改 URL 后可建立 301，并能够检测循环和冲突。
- URL 变更不会改变内容内部身份。

### SEO

- 每个站点、国家市场、Locale 和语言页面均可独立设置标题、H1、描述、关键词、Slug、Canonical、结构化数据和收录状态。
- 系统能显示 SEO 最终值来自全局、站点、市场/Locale、内容类型/模板还是页面覆盖。
- 同一种语言面向不同国家时可以使用不同关键词、标题、内容结构和落地页策略。
- 已发布对应页面自动生成正确的双向 `hreflang`。
- Sitemap 能按语言和内容类型拆分。
- 草稿、预览和被禁止收录页面不会进入 Sitemap。
- robots.txt 危险变更有提醒和审计。

### AI 本土化

- AI 先分析完整语境、目标国家、Locale、受众和搜索意图，再重写目标语言内容，输出不要求与源文逐句对应。
- AI 可重写标题、H1、SEO 标题、描述、关键词、Slug、摘要、正文、Alt、Open Graph 和内链建议。
- 没有真实关键词工具数据时，系统明确标记 AI 关键词为建议，不虚构搜索量和竞争数据。
- 人工锁定字段不会被 AI 修改；源内容变化只标记目标版本需要检查，不自动覆盖。
- 所有 AI 候选默认进入草稿和人工审核，支持逐字段差异、版本审计和回滚，未审核内容不公开发布。

### 性能与数据

- 公开页面支持 CDN 和整页缓存。
- 内容更新只刷新相关页面和缓存。
- 后台列表不读取全部正文。
- 浏览量不直接高频更新内容主表。
- 大批量导入、发布和索引通过任务队列执行。
- 在约定数据规模与硬件环境下通过性能压测。

### 安全

- 管理员支持 MFA。
- 权限可限制到站点和语言。
- 上传文件经过类型、内容和大小校验。
- 关键操作有审计日志。
- 备份可实际恢复，并有恢复演练记录。

### Go、Chi、SQLite与缓存架构

- 应用运行在项目锁定并经过 CI 验证的 Go 稳定版本上，HTTP 路由采用 Chi 并保持 `net/http` 兼容。
- 公开前台与后台由 Go 服务端输出原生 HTML，禁用 JavaScript 时仍能呈现核心内容和执行基础表单操作。
- Go `html/template` 默认自动转义；模板不能执行 Go 代码、SQL、系统命令或读取白名单外服务器文件。
- SQLite 启用 WAL、外键、锁等待、版本化迁移和可恢复备份；写事务保持短小且不得包含网络调用。
- 内容审核使用可审计状态机；异步发布使用 SQLite 持久化任务与有界 Go Worker Pool，并实现幂等、租约、重试和死信状态。
- L1 内存和可选 L2 Redis 的缓存失效在 SQLite 提交后执行；Redis 不可用时系统自动降级且输出告警。
- 模块依赖通过 Go `internal` 包边界、接口、静态检查和自动化测试约束。

### 公开前台与系统维护

- 公开页面能够返回正确的 200、301、302、404、410 和维护状态。
- 语言切换只链接真实存在的已发布语言页面。
- 维护、只读和发布冻结模式分别生效且具有审计记录。
- 生产升级可追踪应用版本、迁移版本并具备失败恢复路径。
- 任务、安全和备份失败能够产生站内通知。

## 13. 开发前仍需确认的参数

以下项目不会阻止当前需求规划，但进入架构和数据库设计前必须确认：

1. 第一版需要管理多少个站点和域名；

4. 预计第一年、第三年的内容记录数量；
5. 图片和视频预计总容量；
6. 日访问量、峰值并发和主要访客地区；
7. URL 采用同域名语言目录、语言子域名还是独立国家域名；
8. 模板主要由开发人员制作，还是必须提供可视化编辑；
9. 内容是否需要多人审核和双人发布；
10. 是否存在旧 CMS 数据和旧 URL 需要迁移；
11. 部署在自有服务器还是云平台；
12. 是否需要接入 Search Console、AI 模型服务、关键词数据源、对象存储和第三方 CDN；
13. 是否需要产品、询盘、物流或完整电商功能。
