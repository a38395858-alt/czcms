# CZCMS 网站流量统计设计

## 目标

为每个独立站点提供真实、可追溯、低开销的访问统计。后台使用中文，站点切换器决定查看范围；默认查看当前站点，拥有全局范围的账号可查看“所有可访问站点”的汇总与分站对比。

## 首期功能

1. **总览指标**：PV、独立访客（UV）、会话、跳出率、每次会话浏览页数，并显示与上一等长周期的变化。
2. **时间趋势**：7 / 30 / 90 天及自定义日期区间；按天查看 PV、UV、会话。
3. **热门页面**：路径、页面标题、语言、浏览量、独立访客。
4. **访问来源**：直接访问与来源域名；不保存完整 Referer URL 及其查询参数。
5. **受众分布**：语言和设备（桌面、手机、平板）。
6. **多站点隔离**：所有统计行有 `site_id`；站点切换时重新加载该站数据。全站汇总只允许拥有全局站点范围的 `analytics.view` 用户。
7. **后台权限与审计**：新增 `analytics.view`。系统所有者和管理员默认拥有；接口再次校验站点范围，并记录统计查看审计事件。
8. **数据导出**：后台可将当前站点/全站点、当前日期范围内的趋势、热门页面、来源、语言、设备和分站汇总导出为 UTF-8 CSV；导出使用当前已授权报表数据，不包含原始 IP、Cookie 或完整 User-Agent。

## 采集规则

- 仅采集成功返回的 HTML `GET 200` 页面：首页、文章、栏目和标签归档均包含；后台、API、媒体、Sitemap、robots、表单提交、通用 `/preview/...` 预览链接、重定向、404 与 5xx 不采集。每个站点的独立本地端口（如 `localhost:8081`）按该站点的真实路径统计，便于发布前联调；上线后的生产报表应以绑定域名产生的真实访问为准。
- 遵守 `DNT: 1` / `Sec-GPC: 1`，不写统计 Cookie，也不记录本次访问。
- 过滤常见爬虫 User-Agent；不记录机器人访问。
- 使用两个第一方、`HttpOnly`、`SameSite=Lax` Cookie：一个随机访客标识（用于 UV），一个 30 分钟会话标识（用于会话和跳出率）。数据库仅保存由服务端主密钥 HMAC 得出的不可逆摘要。
- 独立本地端口的统计只用于开发联调；通用预览路径及后台模板/内容预览始终不计入，避免编辑操作污染报表。

## 隐私与保留

- **永不保存**原始 IP、完整 User-Agent、完整 Referer、URL 查询参数、广告参数、Cookie 原值或可识别访客的页面访问日志。
- `analytics_daily`、页面/来源/维度日聚合长期保留，适合大数据量查询。
- 仅为 UV、页面 UV、会话去重保留哈希辅助表 35 天；超过期限自动清理，历史聚合不受影响。
- 不提供跨站访客画像；同一浏览器在不同站点的摘要也使用站点范围派生，不能用于跨站关联。

## 数据模型

| 表 | 说明 |
| --- | --- |
| `analytics_daily` | 每站每日 PV、UV、会话、跳出会话 |
| `analytics_pages` | 每站、每日、路径的 PV / UV 与当前标题、Locale |
| `analytics_referrers` | 每站每日来源域名或 `direct` 的 PV |
| `analytics_dimensions` | 每站每日语言 / 设备维度的 PV |
| `analytics_visitors` | 35 天期 UV 去重摘要 |
| `analytics_page_visitors` | 35 天期页面 UV 去重摘要 |
| `analytics_sessions` | 35 天期会话、页数与最后访问时间 |

## 接口

`GET /api/v1/analytics/overview?site_id={id}&days=7`

- 支持 `days=7|30|90`，或 `from=YYYY-MM-DD&to=YYYY-MM-DD`（最长 366 天）。
- 返回总览、按日趋势、热门页面、来源、语言、设备及每个已授权站点的汇总。
- API 不接受客户端上报事件，采集只发生在服务端公开页面渲染成功后，避免伪造统计。

## 后台页面与操作流程

1. **入口**：左侧导航「流量统计」。默认使用顶部当前站点；下拉可切换任一授权站点，或选择「所有可访问站点」。
2. **筛选**：支持最近 7 / 30 / 90 天，以及开始、结束日期的自定义区间；日期上限为 367 天，结束日期不能早于开始日期。
3. **总览**：PV、UV、会话、跳出率和每会话页数；PV/UV/会话与上一等长周期对比。
4. **分析区域**：PV 日趋势、来源域名、语言、设备、热门页面和分站对比。表格在窄屏下横向滚动，不截断关键数据。
5. **导出**：点击「导出 CSV」下载当前筛选范围。导出的外部文本会防御电子表格公式注入。
6. **权限失败与空状态**：无权限不返回其他站点数据；尚无访问时显示说明与站点管理入口，不能用示例数据伪造真实指标。

## 数据准确性定义

- **PV**：符合采集规则的一次成功 HTML 页面响应；刷新同一页会增加 PV。
- **UV**：同一站点、同一日、同一第一方访客摘要只记一次。不同站点不共享访客标识。
- **会话**：同一站点在 30 分钟内连续访问视为同一会话；新会话的首个页面先作为跳出会话，访问第二页后自动不再算跳出。
- **跳出率**：跳出会话 ÷ 会话数；无会话时不显示比例。
- **来源**：仅按 Referer 的域名聚合，空 Referer 记为 `direct`；不收集完整 URL、UTM 或搜索词。

## 后续版本规划（不在当前首期内）

| 优先级 | 功能 | 实施前提 |
| --- | --- | --- |
| P1 | 站点级每日/每周邮件报表与流量异常告警 | 邮件通道、任务调度与阈值配置 |
| P1 | 转化统计：联系表单成功、询盘、下载、电话点击 | 只记录服务端确认事件，按站点聚合 |
| P1 | Google Search Console 数据：展示、点击、CTR、平均排名 | 用户在系统设置中授权对应 Google 站点，不采集访客个人数据 |
| P2 | 国家/地区分布 | 由 CDN/反向代理提供的国家代码，默认关闭并只保留国家级聚合 |
| P2 | 渠道分组与活动归因 | 独立的活动参数白名单与保留策略，不能保存完整原始查询串 |
| P2 | 访问路径漏斗、页面性能与 Core Web Vitals | 需要额外的聚合采样策略，避免高频明细写入 SQLite |

首期的日聚合表和站点隔离键已为这些功能预留了扩展路径；后续增加维度时仍应保持“聚合优先、原始个人数据不落库”的原则。

## 验收标准

1. 访问站点 A 与站点 B 后，各自报表只能看到自己的 PV / 页面路径。
2. 同一浏览器当天重复打开同页，PV 增长，UV 不重复增长；新会话会影响会话和跳出率。
3. `DNT: 1` 与机器人请求不生成统计记录。
4. 权限不足或没有该站点全站范围的账号无法读取对应报表。
5. 无数据时显示明确的“尚未开始收集”引导，不显示伪造示例数据。
